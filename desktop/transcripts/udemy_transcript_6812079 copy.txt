  "keywords": ["python", "developer"],
  "filters": {"experience_years": 5, "level": "mid-senior"}

* Semantic search → uses embeddings
* Keyword search → uses tokens/terms extracted from query

Q6. What is an embedding?
Correct Answer:
An embedding is a fixed-size dense numerical vector that captures the semantic meaning of text in a high-dimensional space. Similar meanings = vectors point in similar directions.

python
from sentence_transformers import SentenceTransformer

model = SentenceTransformer('BAAI/bge-large-en')

e1 = model.encode("I love dogs")
e2 = model.encode("I adore puppies")
e3 = model.encode("The stock market crashed")

# e1 and e2 will have HIGH cosine similarity (~0.92)
# e1 and e3 will have LOW cosine similarity (~0.10)

Q8. Why cosine similarity over distance metrics?
Correct Answer:

python
import numpy as np

# Two documents about Python
doc1 = "Python is great for data science"          # short doc
doc2 = "Python is great for data science and machine learning \
        and AI and deep learning and NLP"           # long doc

# Their vectors will point in SAME direction
# but doc2 vector will have LARGER magnitude

# Euclidean distance would say they are FAR APART
# because doc2 has larger magnitude

# Cosine similarity ignores magnitude — only measures ANGLE
# So doc1 and doc2 are CORRECTLY identified as similar

def cosine_similarity(v1, v2):
    return np.dot(v1, v2) / (np.linalg.norm(v1) * np.linalg.norm(v2))

# Result is between -1 and 1
# 1.0  = identical direction = same meaning
# 0.0  = perpendicular = no relation
# -1.0 = opposite direction = opposite meaning
Why not Euclidean distance?
* Euclidean measures absolute distance in space
* A long document and a short document about the same topic would be far apart in Euclidean space because the long doc has larger magnitude
* Cosine measures angle only — magnitude doesn't matter
* Perfect for text because length of document should not affect similarity

Q12. What does temperature do inside the model?
Correct Answer:
Temperature scales the logits before softmax in the output layer.

python
import numpy as np

# After the transformer processes your prompt,
# it produces RAW SCORES (logits) for every token in vocabulary

logits = np.array([2.5, 1.2, 0.8, 3.1, 0.3])
# These represent scores for tokens: ["rain", "sun", "cloud", "storm", "wind"]

# SOFTMAX converts logits to probabilities
def softmax(x):
    e_x = np.exp(x - np.max(x))
    return e_x / e_x.sum()

# Temperature = 0.0 (greedy — always pick highest)
# Temperature = 1.0 (standard softmax — balanced)
# Temperature = 2.0 (flat distribution — more random)

def softmax_with_temperature(logits, temperature):
    if temperature == 0:
        # Always pick the highest scoring token
        probs = np.zeros(len(logits))
        probs[np.argmax(logits)] = 1.0
        return probs
    scaled = logits / temperature   # ← THIS is what temperature does
    return softmax(scaled)

print(softmax_with_temperature(logits, 0.1))
# [0.01, 0.00, 0.00, 0.99, 0.00] → almost always picks "storm"

print(softmax_with_temperature(logits, 1.0))
# [0.18, 0.10, 0.07, 0.35, 0.05] → mostly "storm" but others possible

print(softmax_with_temperature(logits, 2.0))
# [0.22, 0.18, 0.17, 0.27, 0.16] → very flat, anything can be picked
Your scenario — Poem on rainy season:

T = 0.0 → Same exact poem every single time — deterministic
T = 1.0 → Different poem each run — creative, varied word choices

Q13. What is Top-P (Nucleus Sampling)?
Correct Answer:
Top-P selects from the smallest set of tokens whose cumulative probability ≥ P

python
import numpy as np

# After applying temperature, we have probabilities:
probs = {
    "storm":   0.35,
    "rain":    0.25,
    "thunder": 0.20,
    "cloud":   0.12,
    "wind":    0.05,
    "sun":     0.03
}

# Sort descending
# storm  → cumulative: 0.35
# rain   → cumulative: 0.60
# thunder→ cumulative: 0.80
# cloud  → cumulative: 0.92  ← Top-P = 0.9 cuts off HERE
# wind   → cumulative: 0.97
# sun    → cumulative: 1.00

# With Top-P = 0.9:
# Only sample from: ["storm", "rain", "thunder", "cloud"]
# "wind" and "sun" are excluded
# This prevents sampling very unlikely/weird tokens

# With Top-P = 0.5:
# Only sample from: ["storm", "rain"]
# Very focused output

# Temperature vs Top-P:
# Temperature → reshapes the ENTIRE distribution (flatter or sharper)
# Top-P       → CUTS OFF the tail of the distribution

# In practice both are used together:
# Temperature = 0.7, Top-P = 0.9 → common production setting

Q14. Why is output token pricing 4-5x higher than input?
Correct Answer:

INPUT PROCESSING (Prefill phase):
==================================
All input tokens are processed IN PARALLEL
"I need a Python developer with 5 years"
 ↓  ↓  ↓  ↓  ↓  ↓  ↓  ↓  ↓  ↓
[processed simultaneously in one forward pass]
→ Very efficient use of GPU
→ Cheap per token


OUTPUT GENERATION (Decode phase):
===================================
Tokens are generated ONE AT A TIME — autoregressively

Step 1: Model reads all input → generates token 1 "Here"
Step 2: Model reads input + "Here" → generates token 2 "are"
Step 3: Model reads input + "Here are" → generates token 3 "some"
... and so on for every single output token

Each step = full forward pass through entire model
→ Cannot be parallelized
→ GPU memory must maintain KV-cache for all previous tokens
→ 4-5x more compute per token than input
Simple analogy:
* Input = reading an entire book at once (fast, parallel)
* Output = writing a book word by word, re-reading everything before writing each word (slow, sequential)

Q15. Why does Random Forest prevent overfitting?
Correct Answer:
Random Forest prevents overfitting through 3 mechanisms:

python
from sklearn.ensemble import RandomForestClassifier

rf = RandomForestClassifier(
    n_estimators=100,    # 100 trees
    max_features='sqrt', # ← KEY: each split uses random subset of features
    bootstrap=True       # ← KEY: each tree trains on random sample of data
)

# MECHANISM 1: BAGGING (Bootstrap Aggregating)
# Each tree trains on a DIFFERENT random sample of training data
# (with replacement — same row can appear multiple times)
# Tree 1 trains on rows: [1,1,3,5,7,7,9...]
# Tree 2 trains on rows: [2,3,3,4,6,8,8...]
# Each tree overfits its OWN sample — but differently
# When averaged, the overfitting CANCELS OUT

# MECHANISM 2: FEATURE RANDOMNESS
# At each split point, only sqrt(n_features) are considered
# If one feature is very dominant, not every tree will use it
# Forces trees to learn from DIFFERENT features
# Creates DECORRELATED trees — key to variance reduction

# MECHANISM 3: AVERAGING / VOTING
# Regression: final = average of all 100 tree predictions
# Classification: final = majority vote of all 100 trees
# Averaging reduces VARIANCE without increasing BIAS
# This is the bias-variance tradeoff working in your favor

# A single decision tree = low bias, HIGH variance (overfits)
# Random Forest = low bias, LOW variance (generalizes well)

Q16. Shallow copy vs Deep copy
Correct Answer:

python
import copy

# SHALLOW COPY
# Creates new outer object
# BUT inner nested objects are still REFERENCES to originals

original = {"name": "Alice", "scores": [90, 85, 92]}
shallow = copy.copy(original)

shallow["name"] = "Bob"          # Does NOT affect original
shallow["scores"].append(100)    # DOES affect original — shared reference!

print(original)
# {"name": "Alice", "scores": [90, 85, 92, 100]}  ← scores changed!


# DEEP COPY
# Creates new outer object AND recursively copies all nested objects
# Completely independent — no shared references

original = {"name": "Alice", "scores": [90, 85, 92]}
deep = copy.deepcopy(original)

deep["name"] = "Bob"
deep["scores"].append(100)

print(original)
# {"name": "Alice", "scores": [90, 85, 92]}  ← unchanged!


# PERFORMANCE
# Shallow copy → O(1) for flat objects — just copies references
# Deep copy    → O(n) — must traverse and copy entire object graph
# Shallow is faster BUT dangerous if you mutate nested objects
