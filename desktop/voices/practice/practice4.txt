AI Engineer Test
Case Study: DocAssist+
Build an AI assistant that:
 Answers questions from documents (RAG)
 Detects user intent (Question, Complaint, Request, Feedback)
 Detects user emotion (Happy, Neutral, Frustrated, Angry)
 Adjusts response based on intent and emotion

Sample Context
Document:
“Returns are accepted within 7 days of delivery. Refunds are processed within 5
business days.”
Queries:
1. What is your return policy?
2. This is ridiculous, my refund is still not processed

Section F
Problem Statement
 
Build a VoiceBot for Customer Support that can:
 
Understand user input (text or voice)
 
Identify user intent
 
Maintain conversation context across multiple turns
 
Respond intelligently
 
Handle basic real-world scenarios (status check, complaint, query)
 
Scope of Work
1. Core Flow (Mandatory)
 
Build an end-to-end system:
 
User Input → Intent Detection → Context Handling → Response → Output
Minimum Requirements:
 
API-based system (FastAPI / Flask preferred)
 
LLM integration (OpenAI / open-source)
 

STT/TTS optional (can mock)
 
2. Intent Handling (Mandatory)
 
Support minimum 3 intents:
 
Check Status
 
Raise Complaint
 
General Query
 
System should correctly identify and route queries.
 
3. Context Handling (MANDATORY – Most Important)
 
Your system must support multi-turn conversations.
 
Required Scenarios:
Scenario 1: Slot Filling
User: Check my loan status
Bot: Please provide Loan ID
User: 12345
Bot: Your loan is approved
Scenario 2: Context Continuity
User: I want to raise a complaint
Bot: Please describe your issue
User: Payment failed
Bot: Complaint registered (Ticket ID: 5678)
User: What is the status?
Bot: Your complaint (Ticket 5678) is in progress
Scenario 3: Context Switch
User: Check my loan status
Bot: Please provide Loan ID
User: Actually I want to raise complaint
Bot: Sure, please describe your issue
Expected Implementation:
 
Session-based memory (in-memory / Redis / DB)
 
Slot tracking (loan_id, complaint_id, etc.)
 
Ability to reset or switch context
 
4. Prompt Design
 

Design prompts to ensure:
 
Clear, structured responses
 
No hallucinations
 
Proper fallback (e.g., “Connecting to agent”)
 
5. API Design
 
Expose at least:
 
POST /chat → text interaction
 
POST /voice → optional (can simulate)
